# AirText

一个仅面向 Mac 的轻量原生文本传输工具。使用 AppKit 和系统 AirDrop，不包含第三方依赖、自建网络传输、账号、遥测或文本历史。

## 构建

需要 macOS、Xcode 或兼容的 Command Line Tools，Swift 5.9 以上：

```sh
bash build.sh
open dist/AirText.app
```

产物 `dist/AirText.app` 支持 Apple Silicon 和 Intel，最低 macOS 13。
运行 `swift test` 可执行文本格式和临时文件处理测试。

## 使用

1. 将同一个 `AirText.app` 复制到两台 Mac 的“应用程序”目录，各启动一次。
2. 开启 Wi-Fi、蓝牙以及系统 AirDrop 接收；两台 Mac 保持靠近。
3. 在发送端输入文本或点击“粘贴”，再点击“通过 AirDrop 发送…”并选择接收 Mac。
4. 接收端在系统 AirDrop 中接收 `Text.airtext`；若系统没有自动打开，双击收到的文件。
5. AirText 显示原文，点击“复制全部”即可使用。也支持“文件 → 打开…”。

传输使用系统 AirDrop，不需要互联网或接入同一个路由器。接收端必须安装 AirText 才能获得对应的打开体验。
文本是 UTF-8，保留空白和换行，单次最多 1 MiB；不是文件传输管理器。
本地构建仅进行 ad-hoc 签名，未进行 Developer ID 签名或 Apple 公证；在其他 Mac 上可能遇到 Gatekeeper 提示。
仅在确认来源可信后，按系统“隐私与安全性”中的提示批准打开，不要关闭系统安全保护。

## 隐私边界

- 系统 AirDrop 加密传输，但 `.airtext` 本身是**明文文件**，不是加密容器。
- 发送端在系统临时目录创建独立目录（权限 `0700`）和文件（`0600`）。系统报告完成或失败后清理；传输期间退出会先提示并尝试清理。
- 系统取消行为由 AirDrop 控制。如果未收到结束回调，临时文件会保留至退出清理。进程崩溃、强制退出或断电可能遗留临时文件：位置通常为 `$TMPDIR/AirText-<UUID>/Text.airtext`。程序不承诺安全擦除 SSD 数据。
- 接收文件由系统 AirDrop 保存（通常在“下载”目录），**不会自动删除**。界面会显示路径；敏感文本使用后请自行删除，且注意备份和同步工具。
- 只在点击“粘贴”时读取剪贴板。点击“复制全部”会将原文写入系统剪贴板，可能被通用剪贴板或第三方历史工具记录、同步；程序不会自动清空或改动其他剪贴板内容。
- 不记录文本日志，不自动发送，不自动执行收到的内容，不将收到的文本渲染为 HTML。
- “清空”会清空当前编辑器及撤销记录，但不代表内存安全擦除，也不会删除接收文件或系统剪贴板。

两台实体 Mac 之间的 AirDrop 发现、接收和系统取消行为需要实际双机验证；单机编译与单元测试不能替代该验证。
